# Kasmine DSL: Insights and Best Practices

This document captures key learnings and insights from working with the kasmine bytecode builder DSL in jafun tests.

## Overview

Kasmine is a type-safe Kotlin DSL for programmatically building Java bytecode. It's used in jafun tests to define expected bytecode and validate that the compiler generates correct JVM code.

## Local Variable Slot Assignment

### How Slot Assignment Works

Kasmine assigns JVM local variable slots automatically as you call `parameter()`, `istore()`, `astore()`, etc. The assignment is order-based:

```kotlin
method {
    parameter("this")      // Gets slot 0
    parameter("x")         // Gets slot 1
    parameter("y")         // Gets slot 2
    iload("x")            // References slot 1
    iload("y")            // References slot 2
}
```

### Key Insights

1. **Order Matters**: The order of `parameter()` calls determines slot assignment. This must match the method signature.

2. **Parameter vs Local Variable**: 
   - `parameter()` is used in kasmine to pre-register local variables for JVM slots
   - It doesn't actually generate code; it just reserves slot indices
   - Once registered via `parameter()`, you can reference the variable by name in instructions

3. **Implicit 'this' in Instance Methods**:
   - Instance methods (constructors, non-static methods) have an implicit `this` reference at slot 0
   - You must manually register it via `parameter("this")` to reference it in bytecode
   - After calling `parameter("this")`, you can use `aload("this")` to load it

4. **Slot Numbering is Internal**: 
   - Kasmine internally tracks a `localVarMap: Map<String, UByte>` that maps identifier names to slots
   - When you call a function like `iload(identifier)`, it looks up the slot and emits `iload <slot>`
   - You never explicitly specify slot numbers; kasmine handles it

### Example: Constructor with Parameters

For a Java constructor `Address(int number, String street)`:

```kotlin
method {
    name = "<init>"
    signature = "(ILjava/lang/String;)V"
    parameter("this")      // slot 0 (implicit in Java)
    parameter("number")    // slot 1 (int parameter)
    parameter("street")    // slot 2 (String parameter)
    
    // Body: call Object.<init>() and initialize fields
    aload("this")                              // Load slot 0
    invokeSpecial("java/lang/Object", "<init>", "()V")
    
    aload("this")                              // Load slot 0
    iload("number")                            // Load slot 1
    putField("Address", "number", "I")
    
    aload("this")                              // Load slot 0
    aload("street")                            // Load slot 2
    putField("Address", "street", "Ljava/lang/String;")
    
    `return`()
}
```

Generated bytecode:
```
0: aload 0           # Load this
2: invokespecial    # Call Object.<init>()
5: aload 0           # Load this again
7: iload 1           # Load number (slot 1)
9: putfield         # Store in field
12: aload 0          # Load this again
14: aload 2          # Load street (slot 2)
16: putfield         # Store in field
19: return
```

## Method Flags and Access Control

### Access Flags Default Values

Different method types have different default access flags in kasmine:

| Method Type | Default `access` |
|-------------|------------------|
| Static method | `9u` = `ACC_PUBLIC \| ACC_STATIC` |
| Instance method | `1u` = `ACC_PUBLIC` (must be set manually!) |
| Constructor `<init>` | `9u` = `ACC_PUBLIC \| ACC_STATIC` (incorrect for constructors!) |

### Critical Issue: Static Methods vs Instance Methods

**Constructors are NOT static** in Java, but kasmine's default for method access is `9u` (ACC_PUBLIC | ACC_STATIC).

When defining a constructor, you MUST explicitly set `access = 1u`:

```kotlin
method {
    name = "<init>"
    signature = "(ILjava/lang/String;)V"
    access = 1u  // ← REQUIRED! Override default to make it non-static
    // ... rest of constructor
}
```

**Without this override**, the generated bytecode will have the ACC_STATIC flag, which is:
- Invalid for `<init>` methods (Java doesn't allow static constructors)
- Causes bytecode verification errors

### Why This Matters

In the jafun test infrastructure, when you call `jvmIr("Address")` to validate a generated value class, kasmine must generate the same bytecode structure. If the access flags don't match, the bytecode verification fails.

## Field Definition

### Syntax

```kotlin
field(access: UShort = 2u, name: String, type: String)
```

### Access Flags for Fields

| Flag | Value | Meaning |
|------|-------|---------|
| `1u` | ACC_PUBLIC | Public field (visible everywhere) |
| `2u` | ACC_PRIVATE | Private field (default in kasmine) |
| `4u` | ACC_PROTECTED | Protected field |
| `8u` | ACC_STATIC | Static field |
| `16u` | ACC_FINAL | Final (immutable) field |

### Value Class Fields

In jafun, value class fields are generated as public:

```kotlin
field(access = 1u, "number", "I")        // public int number
field(access = 1u, "street", "Ljava/lang/String;")  // public String street
```

This matches the compiler's behavior of generating public fields for value class properties.

## Type Descriptors

Kasmine uses JVM type descriptors (as strings):

| Type | Descriptor |
|------|-----------|
| `void` | `"V"` |
| `boolean` | `"Z"` |
| `byte` | `"B"` |
| `short` | `"S"` |
| `int` | `"I"` |
| `long` | `"J"` |
| `float` | `"F"` |
| `double` | `"D"` |
| `String` | `"Ljava/lang/String;"` |
| Custom class `Foo` | `"LFoo;"` or `"Lpackage/Foo;"` |
| Array of `int` | `"[I"` |
| Array of objects | `"[Ljava/lang/String;"` |

## Best Practices

### 1. Pre-register All Local Variables

Always call `parameter()` for every local variable before using it:

```kotlin
// GOOD
method {
    parameter("x")
    parameter("y")
    iload("x")  // Works: "x" was pre-registered
}

// BAD
method {
    iload("x")  // Error: "x" was not pre-registered
}
```

### 2. Match Slot Order to Method Signature

The order of `parameter()` calls must match the JVM method signature:

```kotlin
// If signature is (ILjava/lang/String;)I
// Then order must be:
parameter("this")      // implicit for instance methods
parameter("number")    // int, slot 1
parameter("street")    // String, slot 2

// NOT: parameter("street"), parameter("number")!
```

### 3. Override Access Flags Explicitly

Don't rely on defaults. Always set `access` flags explicitly for clarity:

```kotlin
method {
    name = "<init>"
    signature = "(I)V"
    access = 1u  // Explicit: non-static instance method
    // ... rest
}

method {
    name = "staticHelper"
    signature = "(I)I"
    access = 9u  // Explicit: public static
    // ... rest
}
```

### 4. Use Descriptive Variable Names

Kasmine's decompilation-based comparison means variable names don't affect bytecode correctness, but they affect readability:

```kotlin
// GOOD
parameter("this")
parameter("address")
parameter("increment")

// BAD (ambiguous)
parameter("x")
parameter("y")
parameter("z")
```

### 5. Document Non-Obvious Bytecode

When bytecode is complex or non-obvious, add comments:

```kotlin
method {
    // ... setup code ...
    
    // Call Object.<init>() to initialize parent
    aload("this")
    invokeSpecial("java/lang/Object", "<init>", "()V")
    
    // Set all fields from parameters
    aload("this")
    iload("number")
    putField("Address", "number", "I")
    
    // ... etc
}
```

## Debugging Bytecode Mismatches

When a test fails due to bytecode mismatch:

1. **Check the error message**: It shows both expected (from your jvmIr block) and actual (from compiler) javap output
2. **Look for key differences**:
   - Constant pool entries (differences in strings, method refs, field refs)
   - Instruction sequences (wrong order, missing instructions)
   - Method flags (ACC_STATIC when it shouldn't be, etc.)
3. **Use javap manually**: Generate the class with the compiler and run `javap -v ClassName.class` to inspect the actual bytecode
4. **Cross-reference**: Compare the javap output line-by-line with what you specified in kasmine

## Common Pitfalls

| Pitfall | Cause | Fix |
|---------|-------|-----|
| Bytecode verification error | Missing `access = 1u` on constructor | Add `access = 1u` to `method { ... }` |
| `aload` fails with type mismatch | Passing `Int` instead of `String` | Pass variable name as String: `aload("varName")` |
| Wrong slot numbers in bytecode | Parameter order doesn't match signature | Re-order `parameter()` calls to match JVM signature |
| Field not found in bytecode | Forgot to call `field()` | Add field definitions before methods |
| `invokespecial` fails | Wrong method reference path | Use `java/lang/Object` not `java.lang.Object` |
